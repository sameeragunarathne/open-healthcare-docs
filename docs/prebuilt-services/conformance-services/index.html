Conformance services

FHIR clients discover what a FHIR server supports, and how to authorize with it, from two well-known endpoints. The conformance services publish both for your FHIR APIs, from configuration, so you don't have to hand-write the documents.

Metadata service​

Implements the FHIR capabilities interaction. It returns a CapabilityStatement that lists the resource types and interactions your FHIR server supports.

FHIR version4.0.1
EndpointGET /fhir/r4/metadata
Sourceconformance/metadata-fhirr4-service

Configure and run​

Describe your server in Config.toml. The main settings are:

SettingDescriptionExample
versionBusiness version of the CapabilityStatement.0.1.7
nameComputer-friendly name.WSO2OpenHealthcareFHIR
titleHuman-friendly name.FHIR Server
statusdraft, active, retired, or unknown.active
kindinstance, capability, or requirements.instance
fhirVersionThe FHIR version the server supports.4.0.1
formatSupported formats.["json"]
interactionSupported system-level interactions.["search-system", "history-system"]

Then add a resource entry for each FHIR resource type your server exposes, with its supported interactions and search parameters. The service README lists every setting, including security and resource settings.

cd conformance/metadata-fhirr4-service
bal run
curl 'http://localhost:9090/fhir/r4/metadata'

SMART configuration service​

Implements the SMART App Launch discovery endpoint. SMART apps read this document, at .well-known/smart-configuration relative to the FHIR base URL, to find your authorization endpoints and the SMART features your server supports.

FHIR version4.0.1
EndpointGET /.well-known/smart-configuration
Sourceconformance/smart-config-fhirr4-service

Configure and run​

Set your authorization server's details in Config.toml. The main settings are:

SettingRequiredDescription
authorizationEndpointRequiredThe OAuth 2.0 authorization endpoint.
tokenEndpointRequiredThe OAuth 2.0 token endpoint.
grantTypesSupportedRequiredauthorization_code for SMART App Launch, client_credentials for backend services.
capabilitiesRequiredThe SMART capabilities the server supports.
issuer, jwksUriConditionalRequired when the server supports sso-openid-connect.
scopesSupportedRecommendedThe scopes clients may request.
introspectionEndpoint, revocationEndpoint, managementEndpointRecommendedToken introspection and revocation, and where users manage app access.
cd conformance/smart-config-fhirr4-service
bal run
curl 'http://localhost:9090/.well-known/smart-configuration'

For more on SMART on FHIR, see SMART on FHIR.
