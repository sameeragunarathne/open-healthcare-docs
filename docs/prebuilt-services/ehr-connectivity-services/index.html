EHR connectivity services

The EHR connectivity services put a FHIR R4 API in front of an EHR. Each service handles the EHR's authentication and proxies FHIR requests to it, so your apps and integrations call one consistent API. The services are grouped by FHIR resource category, so you can run only the ones you need.

For the concepts behind EHR integration, see EMR connectivity.

Epic services​

These services connect to an Epic instance, or the Epic FHIR sandbox, using Epic's FHIR API.

ServiceFHIR resourcesSource
AdministrationEncounter, Location, Organization, Patient, Practitioner, PractitionerRole, RelatedPersonepic-fhirr4-administration-api-service
ClinicalAllergyIntolerance, Condition, Procedure, ServiceRequestepic-fhirr4-clinical-api-service
DiagnosticsDiagnosticReport, Observationepic-fhirr4-diagnostics-api-service
FinancialAccount, Claim, ClaimResponse, Contract, Coverage, CoverageEligibilityRequest, CoverageEligibilityResponse, EnrollmentRequest, EnrollmentResponse, ExplanationOfBenefit, PaymentNotice, PaymentReconciliation, VisionPrescriptionepic-fhirr4-financial-api-service
MedicationsImmunization, Medication, MedicationRequest, MedicationStatementepic-fhirr4-medications-api-service
WorkflowAppointment, AppointmentResponse, Schedule, ServiceRequest, Slotepic-fhirr4-workflow-api-service

Configure and run​

Epic uses backend services authentication with a signed JWT. Register an app in the Epic developer portal, then set these environment variables:

VariableDescription
EPIC_FHIR_SERVER_URLThe Epic FHIR server URL.
EPIC_FHIR_SERVER_TOKEN_URLThe Epic token endpoint.
EPIC_FHIR_APP_CLIENT_IDThe client ID of your Epic app.
EPIC_FHIR_APP_PRIVATE_KEY_FILEThe path to the private key file you created for your Epic app.

Run the service, for example the clinical service:

cd ehr-connectivity/epic-fhirr4-clinical-api-service
bal run

Read a resource through it:

curl 'http://localhost:9090/fhir/r4/Condition?patient=<patient id>'
caution

Keep the private key file and client credentials out of source control. Set them as environment variables or secrets in your deployment.

Oracle Health (Cerner) services​

These services connect to Oracle Health (Cerner), or the Cerner FHIR sandbox, using Oracle Health's FHIR API.

ServiceFHIR resourcesSource
AdministrationEncounter, Location, Organization, Patient, Practitioner, PractitionerRole, RelatedPersoncerner-fhirr4-administration-api-service
WorkflowAppointment, AppointmentResponse, Schedule, ServiceRequest, Slotcerner-fhirr4-workflow-api-service

Configure and run​

Set the Oracle Health connection in the service's Config.toml:

baseServerHost = "http://localhost:9090"
cernerUrl = "https://fhir-ehr-code.cerner.com/r4/<tenant id>"
tokenUrl = "https://authorization.cerner.com/tenants/<tenant id>/protocols/oauth2/profiles/smart-v1/token"
clientId = "<client id>"
clientSecret = "<client secret>"
scopes = ["system/Patient.read", "system/Patient.write"]
FieldDescription
baseServerHostThe base host of this service, used in the URLs it returns.
cernerUrlThe Oracle Health FHIR server URL.
tokenUrlThe Oracle Health token endpoint.
clientIdThe client ID of your Oracle Health app.
clientSecretThe client secret of your Oracle Health app.
scopesThe scopes the service requests.

Run the service and read a resource:

cd ehr-connectivity/cerner-fhirr4-administration-api-service
bal run
curl 'http://localhost:9090/fhir/r4/Patient/<patient id>'

Other EHRs​

For an EHR without a prebuilt service, start from one of these services and change the EHR client and authentication, or build a connector in WSO2 Integrator. See EMR connectivity and EMR connector.
